{% comment %} report_units: the units reports.views.dashboard will actually serve an expert's own report for — the same three _own_report tests. It is a real TUPLE, built in core.context_processors as _OWN_REPORT_UNITS, and that matters: written here as a string, "unit in report_units" would be a SUBSTRING test, and "" is a substring of every string — so a seat with no unit passed the guard and was offered a link the view bounces straight back. A tuple makes it membership again, which also makes the empty unit fail on its own without a separate term for it. The "My Report" entry is drawn in three places below (active accordion role, inactive accordion role, and the no-accordion fallback); all three ask this one question, so the three guards say the same thing and a seat whose unit is not one of these is never offered a link the view bounces back. Add a unit to Unit.CHOICES and it has to be added to _OWN_REPORT_UNITS and _own_report together.
