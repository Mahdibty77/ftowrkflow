EVERY ``CompanyReport`` THIS VIEWER WROTE (``created_by=request.user``), ACROSS EVERY COMPANY AT ONCE — never scope-widened, unlike Reports elsewhere in this app (an ordinary Marketing seat sees its own; a Supervisor/GM/admin sees the unit's) — see marketing/services.py::list_reports_for_user's own docstring for why this tab stays the literal, unconditional "mine" regardless of whatever Marketing seat this viewer might separately hold. Rows come from marketing/views.py::_task_report_rows. SAME FILTER CAPABILITIES AS THE REMINDERS TAB — a searchable case picker (equals, against exact document numbers), a searchable company picker (equals, against exact names) and a Jalali date-range pair — but on THIS tab's own natural date field, the report's own ``created_at`` (labelled "Date" below), rather than a reminder's ``due_at``. Same mechanism as every other filter card in this app: static/js/ui.js's own `data-filter-table` pass, reading the plain `data-filter-for="myTasksReportsTable"`/ `data-filter-colname`/`data-filter-mode` attributes below — no JavaScript of this tab's own, unlike the Reminders tab, which layers day/hour pills on top through `marketing/static/marketing/js/my_tasks.js`; this tab has no such grouping and needs none of that script's own machinery. THE CLOSED-REMINDER TIMELINE — a report that closed out a reminder (marketing/reminders.py::close_with_report) carries three frozen timestamps (reminder_set_at/reminder_due_at/reminder_note — see marketing/models.py::CompanyReport's own docstring for why these can only ever be a frozen copy, never a live lookup) alongside its own text. This is where that report actually LIVES, long after my_tasks_add's own `closed_report` confirmation screen (shown once, immediately after closing) has scrolled out of view. Two SEPARATE things used to be crammed into one "Reminder timeline" cell — the frozen note text and the Set → Due → Reported timeline — which read as clutter, so they now live in two different places: the "Reminder note" column holds ONLY r.reminder_note (or "—" for a row with no reminder behind it at all), and the three-point timeline is drawn as its own full-width strip UNDER the row (a second `` whose single `` spans every column), right- aligned, immediately following any row where r.has_timeline is true (marketing/views.py::_task_report_rows's own flag, true iff reminder_set_at is not null). A PLAIN report — never tied to a reminder, whether written from THIS tab's own "Add report" form or, in principle, from anywhere else in the app — gets neither: its note column reads "—" and no timeline strip follows it at all. THE PERSON FILTER/COLUMN (`scope_all` ONLY) IS THE IDENTICAL MECHANISM THE REMINDERS TAB CARRIES — see `_my_tasks_reminders.html`'s own head comment's "THE PERSON FILTER" section for the full reasoning (matched on `r.person_key`, a stable `Person.detail_code`, not the printed name; built by the view off THIS tab's own rows, exactly as `report_client_names` already is for the Company picker beside it). The one difference: a report's `person_name` falls back to its own FROZEN `author` field, not a live account lookup, when its writer's account is gone — see marketing/views.py::_task_report_rows's own docstring. {% endcomment %}
