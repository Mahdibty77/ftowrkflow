{% comment %} The project role chart — every field is its own clickable card now, so this partial is the whole interface: one inline SVG, one reusable modal, one floating status bar for an attach session in progress, and one floating pill for an active query. There is no separate directory tab any more — see marketing/views.py. The chart no longer creates companies (that lives in the Companies tab a later phase builds) — there is no Add button here at all, only search/ attach/inquiry. And the modal's own behaviour is gated by each node's own ``data-kind`` (see marketing/rolechart.py's ``_kind_of``): "label" cards list and tag companies, the "us" card is a read-only case report, and "inert" cards (nothing feeds them this round) open to a plain empty state with only a Close button — see chart_interact.js. NOT boxed and not zoomable. It used to sit in a bordered, fixed-height, scrollable canvas with its own zoom controls; the owner asked for exactly the opposite — no frame at all, no zoom buttons, the chart itself simply scales up and down with the page's own width and stays centred, using as much of the page as it can. So the SVG below carries no width/height attributes of its own beyond the viewBox — see rolechart.css's `.rc-canvas svg{width:100%}` for how that scaling actually happens; nothing here or in chart_interact.js computes a scale any more. KEEP THIS FILE UTF-8: the Persian role names arrive from marketing/rolechart.py rather than being written here, but a literal added later would flatten to "?" under a non-UTF-8 codepage (the same warning static/css/app.css carries). THIS TEMPLATE DOES NO ARITHMETIC. Every coordinate, every path and every count badge is computed in marketing/rolechart.py and arrives on ``chart``. All the interaction — clicking a node, the modal, the attach wizard, the query highlight — lives in marketing/static/marketing/js/chart_interact.js, wired from the data-* attributes each node carries and from window.FT_MARKETING_CHART (set in home.html). {% endcomment %}
